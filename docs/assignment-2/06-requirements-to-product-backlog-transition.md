## 1. Source Requirements
- Functional Requirements: FR1 - FR14
- Non-Functional Requirements: NFR1 - NFR6
- Source document: docs/assignment-1/03-requirements.md

## 2. Backlog Transformation Approach
1. Each FR/NFR is mapped to one or more backlog items.
2. Each backlog item is assigned a priority (Must/Should/Could).
3. Each item receives a story point estimate.
4. Ownership is assigned.
5. Selected items are refined to implementation detail before sprint planning.

## 3. Example Mapping (Traceability)
- FR1 -> PB1 (register/login)
- FR2, FR3, FR4 -> PB2, PB3, PB4 (post and image flow)
- FR5, FR6 -> PB5, PB6 (search/filter)
- FR7, FR8 -> PB7, PB8 (status + contact)
- FR9 -> PB9 (moderation)
- FR10 -> PB10 (edit/delete)
- FR11 - FR14 -> PB11 - PB14 (AI similarity, ranking, explanation)
- NFR1 - NFR6 -> PB15 - PB20

## 4. Agile Working Principle
- The Product Backlog is not fully detailed in a single pass.
- The backlog is a living artifact and is reviewed before each sprint.
- Only the items planned for the current sprint are refined to detailed level (acceptance criteria, technical tasks, tests).

## 5. Expected Output at This Stage
- High-level requirements are traceable in the backlog.
- Sprint-based refinement plan is explicitly defined.
- Priority and estimation information exists for defined items.
